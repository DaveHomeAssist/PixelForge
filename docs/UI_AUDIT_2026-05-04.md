# Pixel Forge UI Audit 2026-05-04

## Summary

Pixel Forge is in solid mid-stage shape. The componentization is real (22 components, 8 hooks, the bulk of state-machine logic moved out of the shell), the dark-mode token system works, `prefers-reduced-motion` is respected, and most icon-only buttons have either `aria-label` or `title`. The two biggest UI risks are (1) modal accessibility is shallow (no focus trap, no return-focus, no Escape on the form modals, and most don't autofocus the first field), and (2) `PixelForge.jsx` is still around 2000 lines holding all the orchestration state, all keyboard wiring, and all clipboard and selection logic that should live in a hook (it explicitly calls itself out as a "Phase 2 refactor target" in inline comments). A third theme: inline styles are scattered through every component (around 70 occurrences) for layout the CSS file already supports. This is technical debt rather than user-facing breakage but it works against the design-token discipline elsewhere.

The biggest near-term user-facing risk is the keyboard shortcut layer in `PixelForge.jsx` (lines 1333 to 1424): one giant `keydown` listener that ignores OS conventions in places (`X` swap-colors fires even when a non-text input is focused as long as `isEditableTarget` is false, but the modals don't trap, so the canvas hotkeys fire while a modal is open). That, combined with no Escape-to-close on `NewDocumentModal`, `ResizeDocumentModal`, `ExportModal`, `HistoryPanel`, `AdjustModal`, and `AISettingsModal`, is the main accessibility gap. Touch (Phase 3) is not yet wired. The CSS at `@media (max-width: 920px)` rearranges layout but the canvas has no pinch or two-finger handlers, so the mobile shell looks ready while the canvas isn't.

## Critical

### a11y: Modal focus trap and return-focus missing across the board
- `src/components/NewDocumentModal.jsx:13`, `ResizeDocumentModal.jsx:13`, `ExportModal.jsx:31`, `AdjustModal.jsx:102`, `AIGenerateModal.jsx:54`, `AISettingsModal.jsx:28`, `HistoryPanel.jsx:3`, `CommandPalette.jsx:19`. None of these capture or restore focus when opening, and none trap Tab. A keyboard user tabbing past the last button hits canvas or menu controls behind the backdrop. Fix: introduce a small `useFocusTrap(ref, { restore: true })` hook (or use `react-focus-lock`) and apply to every `pf-modal` or floating panel.

### a11y: Escape closes only some modals
- `CommandPalette.jsx:11-17`, `AdjustModal` (via abort), `EditorMenu.jsx:68-71` (menu popovers), and `ColorPickerPopover.jsx:64-78` listen for Escape.
- `NewDocumentModal.jsx`, `ResizeDocumentModal.jsx`, `ExportModal.jsx`, `AIGenerateModal.jsx`, `AISettingsModal.jsx`, `HistoryPanel.jsx`, `StatusBar.jsx:44` (help sheet) do not. They only close on backdrop click or explicit Cancel button. Fix: `useEffect` on `open` that listens for `Escape` then calls `onClose`. Critical because Escape is also globally bound in `PixelForge.jsx:1385` to `escapeMarquee()` and `clearSelection()`, so pressing Escape inside an open modal currently mutates the canvas state silently.

### Keyboard: Global hotkeys fire while modals are open
- `src/PixelForge.jsx:1333-1424` registers a `window` keydown handler that drives every shortcut. The handler only checks `isEditableTarget(e.target)` for typing-like keys, but bare letter shortcuts (V, B, M, R, etc.) bail out of the typing guard. Open `ExportModal` via the Cmd+E equivalent and press `R` while the file-name field is *not* focused: the underlying canvas tool flips to Rectangle. Fix: add a `modalOpenRef` (true if any of `modal`, `aiModal`, `exportOpen`, `commandOpen`, `historyOpen`, `adjustModal`, `contextMenu` is set) and short-circuit the handler. Currently `commandOpen` is the only one that even partially hides this because its input is editable and grabs focus.

## High

### a11y: Color picker popover SV gradient is `role="slider"` but not operable by keyboard
- `src/components/ColorPickerPopover.jsx:140-154`. The saturation and value pad has `role="slider"` and `tabIndex={0}` but only handles `onClick` (no `onKeyDown` for arrow keys, no `aria-valuenow`, `min`, `max`). Either drop the role or wire it. Arrow keys shift S and V, Shift+arrow does coarse steps, expose `aria-valuenow`. Fix: drop the misleading `role="slider"` and use `role="application"` with arrow-key handlers, or remove keyboard pretensions and let users use the HEX, RGB, or HSL inputs.

### a11y: Layer rows are clickable `<div>`s with no role or keyboard
- `src/components/LayersSection.jsx:107-145`. Each `pf-layer` is a `<div onClick>` with `draggable`. No `role="button"`, no `tabIndex`, no Enter or Space handler. A keyboard user cannot select a layer at all. Fix: change to `role="button"` with `tabIndex={0}` and add `onKeyDown` for Enter and Space, or wrap content in a `<button>`. Layer reorder via keyboard is also missing; consider an aria-roving-tabindex list with arrow-key reorder.

### a11y: `pf-toolbar`'s 17 tool buttons rely only on title or `aria-pressed` plus a tiny shortcut glyph
- `src/PixelForge.jsx:1617-1630`. Buttons render `<t.icon size={16} />` and a `pf-shortcut` span with the letter. No accessible name visible to screen readers beyond `title` (which most SRs ignore). The tool label is in `t.label`. Fix: add `aria-label={t.label}` to each button (the title remains the tooltip). Also the shortcut span should be `aria-hidden="true"` so SR doesn't read "Brush B".

### a11y: Toast is not announced
- `src/PixelForge.jsx:1918` and `src/components/StatusBar.jsx:36-37`. `pf-toast` uses no `role="status"` or `aria-live`, so screen-reader users get no feedback for "Copied selection", "Brightness adjusted", error toasts, etc. Fix: add `role="status"` and `aria-live="polite"` (or `aria-live="assertive"` for tone "error") to the toast container; same for `clipboardStatus` chip in the StatusBar.

### Keyboard: Cmd or Ctrl+Y conflicts with browser History on Windows
- `src/PixelForge.jsx:1342` binds Ctrl+Y to redo. Fine on Windows, but on Firefox or Windows it also opens History. The Ctrl+Shift+Z alias on line 1341 already covers the redo case; consider dropping Ctrl+Y on platforms where the browser steals it, or accept the dual binding. Low-impact but worth flagging.

### Keyboard: `[` and `]` resize brush even when typing in non-editable tool buttons
- `src/PixelForge.jsx:1418-1419`. These run unconditionally after the `if (typing) return;` guard, but that guard returns early for editable targets, so OK. However, they fire even when a modal is open (see Critical above). Fix flows through the modal-aware guard.

### Layout: Brush cursor element is unconditionally rendered with inline absolute style
- `src/PixelForge.jsx:817-829, 1698`. `brushCursorStyle` is recomputed on every parent render; the div is mounted only when tool is brush or eraser, fine, but the inline style includes `position: "absolute"` etc. that should live in `.pf-brush-cursor` CSS so dark-mode hooks etc. flow through. Currently `border` is hardcoded to specific RGBA values that don't recolor in dark mode (inspectable as a thin blue ring on a dark canvas). Fix: move to `.pf-brush-cursor` class with `--pf-brush-ring` token override in `.pf-dark`.

### Component design: `PixelForge.jsx` is the kitchen sink (around 2000 lines, 30 useState, 15 hooks of orchestration)
- Lines 53 to 106 declare around 30 separate `useState` calls. Lines 1333 to 1424 are a single 90-line keydown handler. Lines 877 to 1063 are clipboard and selection logic that should sit in a `useClipboard` or `useSelectionMask` hook.
- Comments at lines 645, 651, 656, 667, 675 explicitly say "Phase 2 refactor target". These are `useEffect`s mirroring props into draft state (`color1Input`, `layerNameInput`, etc.). The pattern itself is fine, but consolidating into `useEditDraft({source, parser})` would remove 5 effects.
- Fix priority: extract `useGlobalShortcuts({ ...handlers, modalOpen })`, `useClipboardOps`, and `useMarqueeSelection` first.

### Component design: Inline styles vs CSS class drift
- 64 `style={{...}}` literals across components (`grep -c "style={{"`); about 6 in `PixelForge.jsx`. Examples worth flagging:
  - `LayersSection.jsx:48,52,53,77,78,79,80,81,86,89,92,101`. Inline `flex`, `width`, `marginTop`, font sizing. Every one of these has a class that could carry it.
  - `PaletteSection.jsx:78,89,91`, `ToolSettingsSection.jsx:67,77,86,93,106,121,122,128,129,141,159,160`. `marginRight: 4`, `marginLeft: 6/8/12`, `fontSize: 10`, `gap: 6` repeating. Pull into utility classes (`.pf-row-gap-6`, `.pf-stack-gap-8`) or proper component classes.
  - `AIGenerateModal.jsx:56,68,71,81,89` and `AISettingsModal.jsx:30,49,73,77`. Modal width and form margins inline; the `.pf-modal` already supports max-width via `style={{ maxWidth: 480 }}` overrides everywhere, including in `EditorMenu` mobile sheet which uses CSS. Pick one and stick to it.

## Medium

### a11y: `aria-pressed` missing on toggle-style chip buttons
- `src/components/PaletteSection.jsx:46-67`. Recent-color chips and SWATCHES tiles toggle primary or secondary colors but have no `aria-pressed`. The visual `.primary` or `.secondary` ring tells sighted users; SR users get nothing. Add `aria-pressed={color.toLowerCase() === color1.toLowerCase()}`.
- `src/components/EditorMenu.jsx:201` (toolMeta chip) and `:202` (active-layer chip). These read like badges but the active-tool chip should announce as live region or as `aria-current="true"`.
- `src/components/ToolSettingsSection.jsx:96-110`. Brush preset buttons use `aria-pressed`; good. Stroke width and Fill checkboxes are fine.

### a11y: Color picker popover uses fixed positioning but no portal
- `src/components/ColorPickerPopover.jsx:62, 117`. Rendered inline within `PaletteSection`, `SelectionSection`, and `ToolSettingsSection` with `position: fixed`. This works because of high z-index but is fragile to ancestor `transform` (which would re-anchor). Pixel Forge's `.pf` ancestor doesn't currently transform, but the right-panel CSS uses `transform: translateY(-1px)` on layer-row hover (line 867); luckily not an ancestor of the popover. Recommend `createPortal(..., document.body)` for safety.

### a11y: Custom number input arrow-key handler may swallow valid input
- `src/components/ColorPickerPopover.jsx:86-94`. `handleTabInputKeyDown` intercepts ArrowLeft and ArrowRight on the wrapping div, which means inside an `<input type="number">` the arrow keys cannot be used to move the text caret (they jump fields instead). For HEX text input this is broken text-editing UX. Fix: only fire when `event.target.type !== "text" && type !== "number"`, or scope to the chip-tab buttons.

### Keyboard: CommandPalette has no arrow-key navigation in the result list
- `src/components/CommandPalette.jsx:28-44`. Only a `<div>` of buttons. Up and Down arrows don't move selection, Enter only fires the focused button (which on open is the search input). Add roving tabindex or arrow-key handlers plus Enter-on-input-runs-first-result. This is the canonical command-palette pattern users expect.

### Keyboard: Layer reorder shortcuts only do top or bottom
- `src/PixelForge.jsx:1366-1367`. Cmd+Shift+] and Cmd+Shift+[ exist for top and bottom but no Cmd+] / Cmd+[ for "move up" / "move down" by one position (those Photoshop bindings exist; users will reach for them). Add the single-step bindings.

### Focus and state: Modals don't autofocus first input
- `NewDocumentModal.jsx`, `ResizeDocumentModal.jsx`, `ExportModal.jsx`, `AISettingsModal.jsx`, `AIGenerateModal.jsx`. None call `.focus()` on mount. `CommandPalette.jsx:27` uses `autoFocus`, good. `TextEditOverlay.jsx:8-11` autofocuses, good. `AdjustModal.jsx`. Preview canvas is the first focusable thing but isn't focused. Fix: add `autoFocus` to the first text input or use a ref-based focus on open.

### Visual and layout: Magic-number z-index ladder
- `src/PixelForge.css:102 (5), 203 (10020), 301 (10000), 1013 (10000), 1087 (9000), 1279 (10000), 1323 (9999), 1339 (10001), 1581 (10020)`. Toast (9999) is *below* modal-backdrop (10000) so a toast triggered just before a modal opens is hidden. Floating panel (9000) is below toast (9999), fine. Define `--pf-z-menu`, `--pf-z-modal`, `--pf-z-popover`, `--pf-z-toast`, `--pf-z-context` tokens at `.pf` root (or `:root`) and use them throughout.

### Visual and layout: Sticky menu uses `z-index: 5` while floating bits are 9000+
- `src/PixelForge.css:102`. Works in practice because nothing else competes at that level inside `.pf-body`, but if a future panel inside `.pf-rpanel` uses `position: sticky` with `z-index: 6`, it'll overlap the menu shadow. Bump to a token-driven value.

### Visual and layout: `.pf-toast` uses `aria-live` nowhere; tone styling is only via class
- `PixelForge.jsx:1918`. `<div className={...}>` only. See a11y note above. Also tone "error" produces a shake animation that ignores `prefers-reduced-motion` because the rule at line 1450 to 1454 is keyframes definition and the toast `animation:` shorthand at line 1335 references `pf-toast-shake`. The global `prefers-reduced-motion` rule on line 1526 covers it, so this is actually fine. Withdraw concern.

### Visual and layout: Color well stack overlap is hard-coded
- `src/PixelForge.css:436`. `.pf-color-well.secondary { margin-top: -10px; margin-left: 12px; }`. Cute layered look, but the secondary well covers part of the primary's input-color hit area and on some pointer paths a click intended for primary lands on secondary. Either make stacking obvious with a clearer offset or use a proper toggle UI.

### Visual and layout: Status bar hints text is desktop-only and very long
- `src/components/StatusBar.jsx:42`. `Space drag pans · Scroll zooms · Cmd+V pastes · X swaps colors · [ ] resizes brush`. On a narrow window this wraps awkwardly. The component already swaps to a `?` button on coarse pointers, but not on narrow viewports. Fix: also hide hints on `width < 720px` and show the help button.

### Visual and layout: `.pf-mini-grid` is named "grid" but uses `display: flex`
- `src/PixelForge.css:970-978`. `.pf-mini-grid { display: flex; }` then `.pf-mini-grid.four { grid-template-columns: none; }` (which has no effect because parent isn't grid). At line 1574 the mobile `.pf-mini-grid.four { grid-template-columns: repeat(2, ...); }` again sets a property that's ignored because parent isn't grid. The visual works on flex, but the class names are misleading. Fix: pick grid or flex; if grid, set `display: grid` on the base.

### Component design: Repeated section-header markup
- `LayersSection.jsx:49-55`, `PaletteSection.jsx:39-42`, `SelectionSection.jsx:81-84`, `ToolSettingsSection.jsx:49-52`, `TextPropertiesSection.jsx:18-21`. All render the same `<button className="pf-section-head pf-section-toggle" onClick={onToggle} aria-expanded={!collapsed}>...ChevronDown or ChevronRight...</button>`. Extract a `<SectionHeader title={...} collapsed={collapsed} onToggle={onToggle} meta={...} />` component (around 6 lines, removes 6 copies of the same pattern).

### Error and loading: `applyImageEffectAsync` errors are silently swallowed
- `src/components/AdjustModal.jsx:64-66, 95-97`. `.catch(err => { if (err?.name !== "AbortError") previewRef.current = null; })`. A real preview failure leaves the user staring at the previous preview frame with no error toast, and on commit failure the modal stays open with no feedback. Fix: surface a `pf-field-help warn` row in the modal body and / or call the parent's `flash()`.

### Error and loading: AIGenerateModal swallows non-Error thrown values
- `src/components/AIGenerateModal.jsx:42`. `setError(err.message || "Generation failed.")` is fine when `err` is an Error, but if the AI module throws a string or `{}` the user sees "Generation failed." with no detail. Acceptable for now but consider stringifying unknowns.

### Error and loading: ErrorBoundary doesn't reset on recovery
- `src/components/ErrorBoundary.jsx:33-50`. Only "Reload" or "Copy Report" actions. No "Try again" path that resets `state.error = null`. For a render-time error like a stale layer reference after undo, a reset that clears the boundary and re-renders the children might be enough. Add a "Try again" button that does `this.setState({ error: null })`.

### i18n: Hardcoded English everywhere; ambiguous casing
- All `flash()` strings (`"Cropped to selection"`, `"Brush opacity carries…"`, `"Trimmed transparent edges"`, etc.) and TOOL_COPY in `constants.js`. No i18n harness. Acceptable for a v1 but worth noting.
- Inconsistency: `EditorMenu.jsx:170` says "Rotate 90" (no degree symbol or unit) but the sibling `Crop Selection`, `Trim Canvas`, `Resize Canvas` are noun-phrases. "Rotate 90°" or "Rotate 90 CW" would be clearer.
- `LayersSection.jsx:143`. Lock indicator is the literal letter "L" / "-" with no aria text. Fix: render a Lock or Unlock icon (consistent with the rest of the UI which uses lucide-react) or at minimum include `aria-label`.
- `EditorMenu.jsx:214`. Chip labelled `Cmd` to open Command Palette; opaque on Windows or Linux. Use the existing `pf-kbd` look with "⌘K" or "Ctrl K" appropriately.

### Component design: `PixelForge.jsx` `viewportContextItems` and `layerContextItems` array literals on every render
- `src/PixelForge.jsx:1271-1330`. Both are `useCallback` so the wrapping function memoizes, but each call still constructs around 12 to 15 fresh objects. Fine for a context menu opened on click; just noting that ContextMenu re-renders are throwaway anyway.

## Low and Nits

### a11y: Mobile menu sheet has `role="dialog"` but no `aria-labelledby`
- `src/components/EditorMenu.jsx:217`. `aria-label="Editor menu"` works but using `aria-labelledby="pf-mobile-menu-title"` referencing the brand element is more idiomatic.

### a11y: `<output>` in AdjustModal lacks an explicit `for`
- `src/components/AdjustModal.jsx:128`. `<output aria-label="Amount value">{amount}</output>` reads OK; an explicit `htmlFor` linking to the slider input would be ideal but not required.

### a11y: DraftRecoveryBanner has no role or aria
- `src/components/DraftRecoveryBanner.jsx:10`. Surface as `role="region" aria-label="Autosaved draft recovery"` so AT users notice it.

### a11y: `pf-color-button-label` "P" or "S" letters convey primary or secondary visually only
- `src/PixelForge.jsx:1634, 1639`. Fine because the wrapping `<input>` has `aria-label="Choose primary color"`, so SR announces the right thing. Just noting.

### Keyboard: Hand tool ('H') has no visual difference from Move ('V') beyond the icon
- `src/constants.js:91-92`. Both have raster, vector, text true. UX nit: tooltip on each could clarify "Move shapes or layers" vs "Pan only".

### Keyboard: `Cmd+D` and `Cmd+J` both duplicate
- `src/PixelForge.jsx:1345-1356`. Cmd+D is also "bookmark" in browsers (suppressed via preventDefault, so OK). Cmd+J is what Photoshop uses. Both work; just note this is intentional dual-binding.

### Visual and layout: `cursor: crosshair` on viewport never adapts to the active tool
- `src/PixelForge.css:490`. Base cursor is crosshair, but `cursorStyle` from `useDerivedState` is set inline at line 1648. The Hand tool should set `cursor: grab` (it likely does, please verify in `useDerivedState.js`); if not, add it.

### Visual and layout: `.pf-mbtn` font-size 11px and `.pf-chip-btn` 10px is below WCAG suggested minimum 12px
- `src/PixelForge.css:139, 703`. At standard browser DPR these read fine because of font choice and weight, but on low-DPI Windows displays the menu bar starts feeling cramped. Consider 12px for `.pf-mbtn` and 11px for `.pf-chip-btn`.

### Visual and layout: Two duplicate `prefers-reduced-motion` blocks
- `src/PixelForge.css:1526-1534` and `src/PixelForge.css:1638-1645`. Same media query twice with overlapping rules (`animation-duration: 1ms` vs `animation: none`). The second block wins; the first is dead. Consolidate.

### Visual and layout: Color well "P" or "S" labels don't meet 4.5:1 contrast on light variants
- `src/PixelForge.css:445`. `color: rgba(16, 24, 32, 0.68)` over the swatch background. When the swatch is yellow or white, contrast is OK; over `#ffffff` swatch it's marginal. Acceptable because it's a label not body text, but consider bumping alpha.

### Visual and layout: Truncation only on layer name, not layer tag stack
- `src/PixelForge.css:927-934, 935-940`. `pf-layer-name` truncates with `text-overflow: ellipsis`. `pf-layer-meta` is `flex-wrap: wrap`, so a layer with many tags (`mask`, `clip`, `blend`, `effect`, `78%`) stacks tags onto multiple lines and the row gets tall. Fine, just inconsistent with the row's compact ambition. Consider hiding tags beyond N with a `+2` overflow chip.

### Component design: `useEffectEvent` import is from React 19 experimental
- `src/PixelForge.jsx:1, 719`. `useEffectEvent` is a React experimental API. Make sure CI catches when it's gone-stable or renamed. Not a UI bug, just a project-stability flag.

### Dead and duplicate: `clipboardRef.current = null` set in places that unconditionally re-set it
- `src/PixelForge.jsx:898-902, 911-913, 915-918`. Minor; a no-op assignment.

### Component design: `ColorPickerPopover` "Save Palette" button always saves a single-color palette
- `src/components/ColorPickerPopover.jsx:226-240`. The input is for the palette name and the "Save Palette" button calls `palettesApi?.savePalette?.(paletteName, [hex])`. Saving a palette of one color is a confusing UX; most users will expect "Save current color to selected palette". Either rename to "Save Color" or "Add To Palette" or wire it to a multi-color builder.

### Visual and layout: `.pf-mobile-menu-grid` uses 2-column grid for around 17 buttons
- `src/components/EditorMenu.jsx:223-247`. That's 9 rows of 2 buttons. With finite vertical room on phones, items get scroll-clipped. Reflowing to a 3-column grid on portrait phone would help. Also the sheet itself doesn't scroll (`pf-mobile-menu-sheet { overflow: hidden }` line 314); content overflows silently.

### Copy: Save button label inconsistent across surfaces
- `EditorMenu.jsx:140` (menu item) uses `saveButtonLabel`, line 196 (toolbar) too, line 229 (mobile) too. So this is consistent. Withdraw.

## Recommendations (prioritized)

1. **Modal a11y pass (high leverage, around half a day).** Build `useFocusTrap` plus Escape-to-close plus autofocus plus return-focus, apply to all 8 modal and panel components. Resolves three Critical findings in one go.
2. **Modal-aware global hotkey gate.** Wrap the keydown handler in `PixelForge.jsx` so it short-circuits while any modal or popover is open. Pair with #1.
3. **Delete the macOS `* 2.*` duplicates and move the repo off `~/Desktop`.** Per `_plan/production-readiness.md:177`. Instant win, removes 16 stale files from grep and test-discovery.
4. **Extract `useGlobalShortcuts` and `useClipboardOps` from `PixelForge.jsx`.** Cuts around 250 lines and lets you add the modal gate (#2) with a single prop.
5. **Layer-row keyboard support.** Make `pf-layer` a real button (or `role="button" tabIndex={0}` with Enter and Space handlers). Pair with arrow-key reorder if you have time. Unblocks one of the most-used regions of the app for keyboard users.
6. **z-index token system.** Five tokens (`--pf-z-menu`, `popover`, `floating`, `modal`, `toast`, `context`) eliminate the magic-number ladder and the toast-under-modal bug.
7. **SectionHeader extraction.** Six section components share the same toggle-header pattern; one extract removes around 30 lines of duplicate JSX.
8. **Toast and clipboardStatus to live region.** `role="status"` and `aria-live="polite"` for SR users. One-liner per location.
9. **Toolbar tool buttons get `aria-label={t.label}` and `aria-hidden` on the shortcut span.** One-liner.
10. **Phase 3 touch wiring (per existing plan).** Pinch-zoom plus two-finger pan. The CSS shell is ready; the canvas isn't.
11. **Inline-style audit.** Replace the 64 `style={{}}` literals with utility or component classes; document spacing scale (4 / 6 / 8 / 10 / 12 / 14) as CSS tokens.
12. **Consolidate the duplicate `prefers-reduced-motion` block in `PixelForge.css`.** Trivial cleanup.
